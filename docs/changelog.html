Mucc 1.4.1 (October 27, 2026)¶

  • Smaller: the single binary is 2.8 MB (was 8.8). Its headers and C library are compressed inside it (mucc -pack) and unpacked as they're read; a link unpacks only the members of libc.a it takes, so it's as fast as before.
  • Faster: sqlite3.c compiles in 0.50 s (was 0.79), and mucc's own source in 0.41 s (was 0.54). The tokenizer, the preprocessor's lookups and the assembler do less per character, and the code mucc makes is better: constants are folded through division, instructions take constants, local variables and members (with their offsets) as operands in place, and arguments that are constants or local variables go straight into their registers. That code runs about as fast as gcc -O0's.
  • The bundled musl's sqrt, lrint, fma and the like are one instruction each on x86-64, not portable C: a loop of sqrt and lrint calls runs 14 times as fast (#12).
  • A link that goes to the system's ld (a linker script, -fuse-ld=bfd) works with the bundled musl (#16).
  • -Wa, options reach the assembler, and the built-in assembler names those it ignores (#17).
  • Functions have their sizes in the symbol table, so profilers and debuggers can tell which function an address is in (#18).
  • __VA_OPT__ as C23 has it: off when the variable arguments expand to nothing, #__VA_OPT__(...), and placemarkers with ## (#3, #4, #5). A token pasted with ## keeps the space before it.
  • New warnings, on by default as with gcc: -Woverflow (char c = 300) and -Wimplicit-int (main() {}); no more false -Wformat warning for enum : long long (#8, #9, #10).
  • fabs, fabsf and fabsl are builtins, so they need no -lm (#11).
  • -fsyntax-only rejects assigning to values that aren't lvalues (#2); a struct too large to lay out is an error, not an "incomplete type" (#7); cross-compiling to ARM64, LDBL_MAX is finite (#6).
  • Undefined behavior in mucc fixed, found by a new CI job that runs the tests with mucc built with AddressSanitizer and UndefinedBehaviorSanitizer (#13, #14, #15).
  • make bench SQLITE3_C=path/to/sqlite3.c times SQLite's amalgamation too, with tcc if it's installed.
  • make fuzz tests mucc with random programs until it's stopped, against gcc, against itself for the other CPU, or with broken input it must not crash on, and keeps what it finds (Fuzzing). The random programs now have floats, and structs of only floating-point members.
  • mucc --help lists the most used options and where the rest are, instead of only a usage line.
  • The parser, which was one file of 9,600 lines, is six, by topic (src/parser.h lists them).
  • A new license: Mucc is now under the Mucc License (was MIT). It's still free for any use, and programs built with mucc are unaffected, but works made from Mucc must credit Dom-Yan, keep “Mucc” in their name, and never be presented as someone else's. Every source file now carries the license header (License).

Mucc 1.4.0 (October 14, 2026)¶

  • 64-bit ARM (AArch64) Linux: mucc runs there and makes programs for it, with its own assembler, linker and runtime library and the bundled musl, as on x86-64. Releases include mucc-aarch64-linux. --target=aarch64-linux and --target=x86_64-linux cross-compile either way. Programs are aligned to 64 KB pages, so they run on kernels with 4, 16 or 64 KB pages (the Raspberry Pi 5's, Asahi Linux).
  • Faster: compiling a small file takes about a fifth of the instructions it did, as the embedded headers are found by binary search and the predefined macros are read only when used; large files take about a fifth fewer.
  • Crashes fixed: a -D value ending in a // comment, pasting / and /, a #define ending a macro argument, division by zero or LONG_MIN / -1 in a constant, and a file-scope array of run-time size (now an error, as with gcc). A file that includes itself stops at a depth of 200.
  • -c, -S, -E and -fsyntax-only with linker inputs (-lm, objects) no longer link, or reject -o.
  • The assembler keeps \" inside a string, as in .ascii "a\";b".
  • Memory leaks in the hash tables are fixed.

Mucc 1.3.0 (October 8, 2026)¶

  • Fixes for wrong code: a file-scope struct or union set from a compound literal (T x = (T){...};) was all zeros; a VLA typedef's length was evaluated again at each use, and its sizeof could be 0 after a branch; __attribute__((vector_size(N))) before the type was ignored; some decimal double and float constants were 1 ULP off; the side effects of __builtin_expect's second argument and of a VLA parameter's length were dropped.
  • A crash on a vector compound literal cast to an integer in a condition is fixed.
  • Valid code now accepted: ATOMIC_FLAG_INIT and ATOMIC_VAR_INIT; unknown attributes (a warning, as with gcc); a member of a struct a statement expression gives; a block-scope extern function declaration hiding a local; gcc's predefined macros for <stdint.h>'s types, the types' widths, __BIGGEST_ALIGNMENT__ and the floating-point limits.
  • Invalid code now rejected: arithmetic and bitwise operators on pointers, ~ on floats, casts between pointers and floats, comparing a pointer with a float, and assigning to, or taking the address of, values that aren't lvalues. Excess initializer elements warn.
  • -funsigned-char, -fno-pic, -ffast-math, -fpermissive and -fms-extensions; -Xlinker is -Wl, and needs no system ld.
  • The assembler: .int, .word, .float, .double, .skip, .space, .fill, .p2align and .balign with fill and maximum (code padded with GNU as's NOPs), .set and .equ with constants and *, /, << and >>, .rept, .macro, .pushsection, .popsection, .ident, merged sections ("aMS"), and .cfi_* (dropped). The same objects as GNU as.
  • -g records const and volatile.
  • The README is a full guide to using mucc, with its limitations, and its numbers are corrected: which real programs were tested with --libc=system, the speed of generated code, and the line count.

Mucc 1.2.1 (October 7, 2026)¶

  • The first release built by mucc alone: 1.2.0 compiled, assembled and linked it, with gcc and binutils made to fail. Otherwise as 1.2.0.

Mucc 1.2.0 (October 7, 2026)¶

  • -g: DWARF debug info, so gdb's print, ptype, info locals and bt show variables, parameters, globals and their types, as on a gcc -g -O0 build.
  • Warnings with names, as with gcc: -Wall adds printf and scanf format checks, if (x = 0), statements with no effect, comparisons with string literals, unused static functions and enum values a switch misses; returning a local's address, division by zero and bad shift counts warn by default. -Werror, -Werror=<name> and -Wno-<name> work.
  • gcc's floating-point builtins (__builtin_isnan, __builtin_inf, __builtin_fabs, __builtin_fpclassify, ...), its C library builtins (__builtin_memcpy, __builtin_strlen, ...), __builtin_choose_expr and __builtin_object_size.
  • Fixes: int x; int x; (the same tentative definition twice, static or not) defines the variable instead of leaving it undefined at link time; ## with empty arguments (x##y##z with x and y empty) and ## in object-like macros paste as C says; typeof_unqual drops const, volatile and _Atomic; a compound literal keeps its type's qualifiers.
  • Fixes in code generation: conversions between unsigned long and floating types from 263 up, compare-and-swap for _Atomic floating types, and structs holding a long double passed as the psABI says.
  • const, volatile, long long and signed char are types of their own, struct layouts with #pragma pack match gcc's, and wchar_t is int, as with gcc and musl.
  • Errors instead of wrong code or a crash: a struct used as a number (if (s), s * 2, s[0], (int)s), a variable defined twice, and an enumerator redeclaring a name.
  • __builtin_offsetof and __PRETTY_FUNCTION__.
  • make -j test-all works.
  • The rest of C and GNU C: __int128 (also as bit-fields), _Complex, asm goto, __auto_type, gcc's vector types with the SSE to SSE4.2 intrinsics headers, __builtin_shufflevector and __builtin_convertvector, K&R function definitions, objects of 2 GiB and more, and -fvisibility=.
  • Releases are built by the release before them, with gcc and binutils made to fail (test/bootstrap.sh); a build is the same bytes whichever compiler starts it, and an object without -g the same in any directory.
  • Smaller and faster: the single binary is 8.5 MB (was 11.3), tokens and AST nodes take less memory (sqlite3.c peaks at 250 MB, was 540), and mucc compiles its own source 2.7 times faster than gcc -O0.
  • More real programs pass their own tests, each a script in test/thirdparty/: redis, jq, GNU make, sed with gnulib's tests, gawk, stb and miniz, besides SQLite, CPython, Git, Lua, zlib, libpng and TinyCC. Bugs they found are fixed: #line inside an #if, a directive after an empty macro, #undef __inline, macros coming back after #undef, and variables' visibility.
  • A deep test before the release: mutation fuzzing (142,000 inputs, 9 crashes fixed), a new preprocessor fuzzer against gcc (6,500 programs), 5,000 random programs, every C and POSIX header under both libcs, and mucc under valgrind. Also fixed: # of a parameter also used expanded, sizeof of a compound literal of unknown length, #define inline __inline__, and <stdbit.h> added.

Mucc 1.1.0 (October 1, 2026)¶

  • Fixes: atomics' fetch operations return the value from before, and atomic stores are sequentially consistent; an enum with no negative values is unsigned, as with gcc; a negative array size is an error.
  • Linux's own headers (Linux 6.18.54) come with the bundled musl, for programs that use the kernel directly. The single binary grows from 7.2 to 10.9 MB.
  • .S files, -x assembler-with-cpp, _Pragma, C23's <stdckdint.h>, offsetof with a member path as a constant, and forward enum E; declarations.
  • gcc's builtins for bit counting, byte swaps, overflow checks and atomics (__sync_*, __atomic_*), and __builtin_expect, __builtin_constant_p and others.
  • The assembler: port I/O, cpuid, rdtsc, MSRs, descriptor tables, fences, bswap, popcnt, .ascii, value lists and label differences.
  • The linker: relocatable links (-r), map files (-Map) and many more -Wl, flags; the driver: -pthread, -nostdlib, -Wp,-MD, and tuning and hardening flags accepted.
  • Code that can't run isn't compiled, as with gcc.
  • Eight Linux programs written from scratch are built by the single binary in an empty root and run on every change.

Mucc 1.0.1 (September 29, 2026)¶

  • mucc --version prints the version.
  • A shorter README, with instructions to build mucc from source using only mucc, without gcc.

Mucc 1.0.0 (September 29, 2026)¶

The first release: a single static binary with its headers and musl inside, which needs nothing else installed.

  • CI tests everything, including Linux distributions and real programs, and the release workflow publishes only the file that was tested, after CI passed.
  • The README explains how to install without sudo, and how to update and uninstall.

Development before 1.0¶

September 28, 2026
  • make build/mucc makes a single binary with the C library inside it. It is a static musl program that runs in an empty container, and its default C library is the musl inside it.
  • --libc=mucc compiles and links against the bundled musl.
  • The single binary builds SQLite, zlib, Lua and mucc itself on four distributions, and rebuilds itself in an empty container.
  • A version tag publishes the single binary through the release workflow.
  • Bugs found by gcc's torture tests are fixed. A VLA is freed when its scope is left. A duplicate case value, or a second default, is an error.
September 27, 2026
  • musl 1.2.6 is vendored, patched for CVE-2026-40200 and CVE-2026-6042, and built by mucc alone with make libc.
  • musl's libc-test runs against the musl that mucc builds, and the long double and NaN bugs it found are fixed.
  • The assembler handles musl's x86-64 .s files.
  • Varargs and arguments on the stack follow the psABI.
September 24, 2026
  • Git builds with mucc and passes its tests. CPython and Git results are added to the README and site.
  • C17 is the default, and -std= chooses the standard.
  • GNU attributes are parsed wherever gcc accepts them, and many are implemented: aligned, packed, weak, used, constructor, destructor, cleanup, alias, section and visibility.
  • GNU asm with operands and register variables.
  • An archiver: mucc -ar and mucc -ranlib.
  • --libc=system, and line markers in -E output.
September 23, 2026
  • Initial commit: a small self-hosting C11 compiler for x86-64 Linux.
  • A built-in assembler and a built-in static linker.
  • Hot variables kept in registers, constant folding, and faster tokenizing and memory allocation.
  • Reproducible builds, and every error in a file is reported, not just the first.
  • GitHub Actions CI and this website.
