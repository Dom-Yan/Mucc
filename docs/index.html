Introduction

Mucc (mucc) is a small, fast, self-hosting C compiler for x86-64 Linux. It is one static file with its own preprocessor, assembler, linker, headers and C library (musl) inside. Copy it onto any x86-64 Linux machine and it builds C programs with nothing else installed: no gcc, no binutils, no system headers.

Why use it

  • Fast builds. It compiles about 4.5 times faster than gcc -O0 and 17 times faster than gcc -O2.
  • Nothing to install. One file of about 11 MB is the whole toolchain. It works in an empty container, on old distributions and on machines with no compiler.
  • Small enough to read. About 22,000 lines of C that you can understand from end to end.
  • Real C. C17 by default, C23 with -std=c23. It builds CPython, Git, SQLite and Lua, which then pass their own test suites.

Use gcc or clang instead when you need the fastest possible generated code, or a target other than x86-64 Linux. Code that mucc generates runs about as fast as code from gcc -O0.

Mission

The goal of Mucc is to provide a fast, portable, reliable compiler for C. Major decisions about the project are made by Dominick, and they are guided by that goal.

In practice, this means:

  • One static file. The compiler, assembler, linker, headers and C library ship together as a single program.
  • No dependencies. Nothing else has to be installed to compile and link a C program.
  • Runs on any x86-64 Linux. New or old distributions, glibc or musl or no C library at all, WSL 2 and empty containers.
  • Small enough to read. The whole compiler can be understood by one person.
  • Correctness first. Every fix comes with a test, mucc must rebuild itself byte for byte, and real projects must pass their own test suites when built with it.

Mucc is feature complete. Changes should make it faster, smaller, clearer or more correct.

Download

Latest release: github.com/Dom-Yan/Mucc/releases/latest
All releases: github.com/Dom-Yan/Mucc/releases

To install on any x86-64 Linux (Ubuntu, Debian, Fedora, Arch, Alpine, WSL 2 and others):

mkdir -p ~/.local/bin
curl -Lo ~/.local/bin/mucc https://github.com/Dom-Yan/Mucc/releases/latest/download/mucc-x86_64-linux
chmod +x ~/.local/bin/mucc
mucc --version

If mucc is not found, open a new terminal or add ~/.local/bin to your PATH. To update, run the same curl again. To uninstall, delete the file. Each release also has a .sha256 file to check the download with sha256sum -c.

Then compile a program:

mucc -o hello hello.c
./hello

Mucc takes the usual gcc flags, such as -c, -S, -E, -o, -I, -D, -l, -L, -static and -std=. Programs are linked statically against the musl inside mucc. To use the system's glibc and shared libraries instead, add --libc=system. Instructions for building from source are in the README.

Where it runs

  • Runs on any 64-bit Intel or AMD Linux, with glibc, musl or no C library at all, including WSL 2, containers and CentOS 7.
  • Does not run on macOS, Windows outside WSL, ARM or 32-bit x86.
  • The programs it builds are x86-64 Linux executables.

What it supports

  • C17 and C23: bool, nullptr, constexpr, auto, #embed, typeof, [[attributes]] and more
  • The full preprocessor, VLAs, _Generic, atomics, thread-local variables, structs by value, varargs
  • GNU extensions: statement expressions, computed goto, case ranges, __attribute__, extended asm
  • New in 1.1.0: Linux's own headers (<linux/*.h>), .S files, <stdckdint.h>, gcc's bit-counting, overflow and atomic builtins, _Pragma, -r and -Map in the linker, and port I/O, cpuid and other system instructions in the assembler
  • On main, not released yet: -g debug info, so gdb shows variables and types; gcc's -Wall warnings with -Werror and -Wno-; gcc's floating-point and C library builtins (__builtin_isnan, __builtin_memcpy, ...)
  • Not supported: C++, _Complex, __int128, _BitInt, asm goto, K&R function definitions, and optimization beyond register allocation and constant folding

Found a bug?

Please report it on the issue tracker. A small C file that shows the problem, the command you ran and what you expected help the most.

Fixes are welcome as pull requests. See Contributing below before sending one.

Contributing

When you contribute to Mucc, the goal is to provide clear code: code that the next person can read and understand. Please be polite and respectful to everyone in issues, pull requests and reviews.

If you use an LLM or another AI tool, make sure you have actually read and understood every line of the code you submit.

The contributing rules are in the README. In short:

  • Run make test-all before every commit, and add a test for each fix.
  • src/ may only use C that mucc supports, since mucc compiles itself.
  • Changes should make mucc faster, smaller, clearer or more correct.

Report problems on the issue tracker and send changes as pull requests.
